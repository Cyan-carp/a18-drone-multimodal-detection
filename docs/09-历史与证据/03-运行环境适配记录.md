# 运行环境适配记录

本页记录搭建与联调过程中实际遇到的 8 个环境问题、定位依据与处理方式。目的不是评判环境，而是让换机复现时不必重走一遍。

## 1. 命令与路径

| # | 现象 | 定位依据 | 处理 |
| --- | --- | --- | --- |
| 1 | `Test-Path` 对仓库路径返回 `False` | 路径含 `[A18]`，方括号被当成通配符字符类 | PowerShell 一律使用 `-LiteralPath`；`Remove-Item` 被环境包装后不支持该参数，改用 `[IO.Directory]::Delete` |
| 2 | 命令无输出且工具报 `No result found` | `Add-Content` 未声明编码，被安全策略拦截 | 显式 `-Encoding utf8`，或改用文件编辑工具 |

## 2. JDK 与 Maven

| # | 现象 | 定位依据 | 处理 |
| --- | --- | --- | --- |
| 3 | `java -version` 返回码 `0xC0000409`，无输出 | `javapath` 是 Oracle 安装垫片，本身不可用；`C:\Program Files\Java` 下只有 `jre1.8.0_291` | 下载便携 JDK 17 到 `.tools/jdk17`，`start-backend.ps1` 优先使用它 |
| 4 | `mvn` 不存在，`~/.m2` 为空 | `Get-Command mvn` 失败；目录为空 | 脚本从华为云下载 `apache-maven-3.9.9-bin.zip` 解压到 `.tools/maven`，生成 `.tools/settings.xml`（阿里云镜像 + 本地仓库） |

## 3. Node 与前端

| # | 现象 | 定位依据 | 处理 |
| --- | --- | --- | --- |
| 5 | 系统 Node 22.11 加载任意 `node_modules` 模块即崩溃 `0xC0000005`（`require('react')`、`tsc`、`vite` 全崩，`node -e` 正常） | 隔离测试：`node -e` 正常、`require('./probe.cjs')` 正常、`require('react')` 崩溃；换 Node 20 后同一命令正常 | 下载便携 Node 20 到 `.tools/node20`，脚本优先使用；同时清空注入的 `NODE_OPTIONS`（`--require` 语言垫片） |
| 6 | `npm install` 在 esbuild 的 `node install.js` 阶段崩溃 | 安装日志 `npm error code 3221225477 / path ...node_modules\esbuild` | 改用 `npm install --ignore-scripts`；平台二进制由 `@esbuild/win32-x64` 提供，构建不受影响 |
| 7 | Vite 配置报 `allowedHosts` 不存在于 `ServerOptions` | `tsc --noEmit` 报 TS2769，Vite 5 无该选项 | 移除 `allowedHosts`，保留 `host: 0.0.0.0` 与 `/api` 代理 |

## 4. 渲染与数据

| # | 现象 | 定位依据 | 处理 |
| --- | --- | --- | --- |
| 8 | 画布标签在缩略尺寸下不可读 | 初版按 1024 原始像素绘制，显示到 250px 时字号折算不足 5px | `DualCanvas` 改为按容器像素 × DPR 绘制，坐标乘显示比例，`ResizeObserver` 触发重绘 |

## 6. 结论

上述处理均已固化进脚本与代码（`scripts/*.ps1`、`scripts/*.cmd`、`vite.config.ts`、`DualCanvas.tsx`），不依赖人工记忆。若换机后仍出现同类崩溃，先核 `.tools/node20` 与 `.tools/jdk17` 是否被使用。
